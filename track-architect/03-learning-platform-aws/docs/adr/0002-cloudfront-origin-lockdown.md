# ADR 0002: CloudFront as the only front door; ALB locked to it

Status: accepted

## Context
Users need low-latency static assets and an API under one domain. An internet-facing ALB can be reached directly unless it is restricted, bypassing any edge protections (WAF, caching, TLS policy).

## Decision
- One CloudFront distribution: default behavior serves a private S3 bucket through Origin Access Control; `/api/*` is forwarded to the ALB with caching disabled.
- The ALB security group admits only the **CloudFront origin-facing managed prefix list**, and the listener returns **403 unless** the request carries the `X-Origin-Verify` header with a secret generated by Terraform. The prefix list alone is not enough: any CloudFront distribution in any account can use those IPs, so the header is the identity check.
- Prod uses HTTPS from CloudFront to the ALB (regional ACM certificate on a name that CloudFront uses as origin); dev uses HTTP between CloudFront and the ALB to avoid needing a domain and certificate.

## Consequences
- Direct requests to the ALB DNS name fail.
- The secret lives in Terraform state and in the CloudFront origin config; rotate it by changing the random value (brief mismatch window: rotate in two steps with two accepted values for zero downtime, not implemented here).
- The managed prefix list counts against the security group rules quota; request an increase if the group also carries many other rules.
- Follow-ups not in the baseline: WAF web ACL, CloudFront and ALB access logs, Shield Advanced where warranted.
